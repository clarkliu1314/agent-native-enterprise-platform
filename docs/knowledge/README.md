# 项目知识库

本目录是 Agent-native 企业系统项目的长期知识沉淀区。所有文档强制使用中文；代码符号、API 名称、框架名称、Commit SHA、CI Run ID 等技术标识保留原文以便检索。

## 文档地图

| 文档 | 用途 |
|---|---|
| `01-技术选型与决策记录.md` | 记录早期技术选型、比较逻辑、采用与否的原因 |
| `02-架构设计与核心原则.md` | 记录总体架构、边界和不可变不变量 |
| `03-正式细化阶段与规格演进.md` | 记录从架构到可执行规格的演进 |
| `04-编码实现阶段与工程演进.md` | 记录正式编码、关键实现、CI 修复和工程经验 |
| `05-Benchmark与验证体系.md` | 记录 16 Case、64 Matrix 和验证分层 |
| `06-CI故障与工程经验.md` | 记录典型 CI 故障、根因和防回归原则 |
| `07-项目知识总览与后续演进指南.md` | 作为新成员/新 Agent 恢复项目上下文的入口 |

## 正式规格与计划

架构和实现的正式规格仍以 `docs/superpowers/specs` 与 `docs/superpowers/plans` 为准。本目录主要承担跨阶段知识沉淀和决策记忆，不替代正式规格。

## 更新规则

- 技术决策变化 → 更新 01。
- 架构边界变化 → 更新 02 + 正式 architecture/spec。
- 规格变化 → 更新 03 + 正式 spec。
- 实现/CI 重要变化 → 更新 04/06。
- Benchmark 变化 → 更新 05 + Benchmark spec。
- 阶段完成度变化 → 更新 assessment。
- 新 Agent 开始工作 → 先阅读 07，再阅读相关正式 spec/plan。

## 记忆原则

本目录视为项目的**持久化工程记忆**：重要判断不能只存在聊天上下文中。所有未来会影响架构、实现、验证或业务边界的关键结论，都应在这里留下可审计记录。
