## 3. 当前权威边界

### 应用层

依赖 Runtime Contract，不直接依赖具体 Framework。

### Runtime

负责 durable execution 和 Agent lifecycle。

### Tool Runtime

负责 Permission、Idempotency、Tool execution、result persistence 和 Outbox boundary。

### Recovery

负责 durable candidate、lease、reclaim、retry、terminal failure。

### Adapter

负责把具体 Framework 映射到统一 Runtime Contract。

### API/Vercel

只负责 request boundary。

### Worker

负责长期执行、Recovery、Outbox、并发协调。

### PostgreSQL

权威 durable state。

## 5. 任何未来开发必须遵守的原则

1. 先确认属于平台核心还是业务域。
2. 平台核心优先修改 contract/spec，再修改实现。
3. 新行为先写失败测试。
4. 不用 Framework API 污染 Runtime Contract。
5. 外部副作用必须经过 Permission + Idempotency。
6. 状态与 Outbox 必须有明确事务边界。
7. Recovery 必须可脱离 HTTP request 独立运行。
8. 真实基础设施问题不能长期用 deterministic fake 掩盖。
9. 所有重要结论必须带验证证据。
10. 文档中的“完成”必须注明完成层级。

## 6. 面向股权投资管理业务域的入口条件

底座通过 Go/No-Go 后，业务域应建立在 Runtime Contract 之上。业务实体、工作流、审批、投资机会、基金、项目、尽调、投决、投后管理等都不能反向修改平台核心 durable execution 语义。

推荐业务域依赖关系：

```text
Investment Application
        ↓
Business Agent Workflows
        ↓
Runtime Contract
        ↓
Durable Agent Runtime
        ↓
PostgreSQL / Outbox / Recovery
```

## 8. 状态词汇表

- **设计完成**：设计已确定。
- **实现完成**：代码已存在。
- **验证完成**：自动化验证已通过。
- **deterministic-only**：确定性 fixture 已验证，真实基础设施尚未验证。
- **production primitive**：核心 primitive 已按生产语义实现。
- **production integrated**：真实基础设施/SDK/并发链路已经接入并验证。
- **ready for business domain**：满足 Go/No-Go 门槛，可以进入业务域。
